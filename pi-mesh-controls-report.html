工具面与入口判定

Host 工具与 Child 工具严格分离。设置 PI_MESH_CHILD=1 时，主 extension 不注册 Host 工具。

Host 工具

meshAgentget_subagent_resultsteer_subagent
  • mesh：持久化 DAG 编排。
  • Agent：单一 session-centric 子 Agent。
  • get_subagent_result：等待或读取后台结果。
  • steer_subagent：仅运行中的 Agent 可 steer。

Mesh actions

list_agents · run · status · list · cancel · pause · resume · recover · steer · handoff_list · message_send · message_broadcast · message_inbox · message_ack · growth_list · growth_decide

所有参数对象均设置 additionalProperties: false。

Child-only 控制面

mesh_control

仅 Mesh Child 注入，actions 为 send / broadcast / reply / inbox / ack / grow。Direct Agent 不获得它。

03

项目信任、Agent 发现与资源判定

Agent 来源优先级

  1. Bundled：package agents/*.md
  2. User：getAgentDir()/agents
  3. Project：最近的 .pi/agents，仅可信项目

同名时后加载来源覆盖前者。未知 Agent 类型严格失败，不回退 general-purpose。

项目 Trust gate

  • 未信任：不加载项目 Agents。
  • 未信任：不加载项目 settings 和 Child resource maps。
  • 创建项目 Agent 必须 trusted。
  • Manager key 包含 root、trusted、sessionId。

Agent 文件判定

  • 必须是普通 .md 文件，symlink 目录/定义忽略。
  • description 必填；name 可回退到文件名。
  • enabled: false 不加载。
  • max_turns 仅接受正整数。
  • 不可读或 malformed 定义忽略；list_agents 可见缺失。

Child 资源白名单

  • Child 默认 --no-extensions --no-skills。
  • 只按逻辑名解析 childExtensions/childSkills。
  • Agent 文件中的 wildcard、绝对路径、路径分隔符导致该定义被跳过。
  • 配置目标必须存在、不是 symlink、且为文件或目录。
  • 禁止在 Child 内加载 pi-mesh / pi-subagents / subagents。

05

Mesh DAG、Operators 与生命周期

创建校验

  • 初始 tasks：1–min(32, maxNodes)。
  • Node ID：[A-Za-z0-9][A-Za-z0-9._-]{0,63}。
  • 任务文本 ≤ 64 KiB。
  • retries：0–5。
  • timeout：100 ms–1 h。
  • CWD 必须在 Run root 内。
  • 依赖必须存在、DAG 无环、深度不超过 maxAgentDepth。

8 个 Operator

graphsequenceparallelracesupervisormixturereflectiondebate
  • sequence/reflection/debate：顺序链。
  • supervisor/mixture：workers → final。
  • race：首个成功后取消其余。
  • 它们是 topology presets，不是八套独立推理引擎。

运行判定

  • 依赖全部 succeeded 才 ready。
  • 依赖 failed/cancelled/skipped → 当前节点 skipped。
  • failFast：首个失败后终止剩余。
  • 结果按 attempt generation fencing，迟到结果不可覆盖。
  • 更新回调最多每 500 ms 一次。
// Node transitions
queued  → running | paused | cancelled | skipped | failed
running → queued | paused | succeeded | failed | cancelled
paused  → queued | cancelled | failed
terminal → no transition

// Run transitions
running    → paused | cancelling | succeeded | failed | cancelled
paused     → running | cancelling | cancelled
cancelling → cancelled | failed | succeeded
06

Child 进程、Timeout 与取消升级

RPC Child

  • 独立 Pi 进程，Unix 使用独立 process group。
  • cooperative abort。
  • 3 秒未结束 → SIGTERM。
  • 再 3 秒未结束 → SIGKILL。
  • 关闭同样 SIGTERM → 3 秒 → SIGKILL。
  • stdin EPIPE 被吸收并转换为 session closed。

协议边界

  • 单行 stdout 最大 4 MiB，超限终止 Child。
  • stderr 仅保留最后 128 KiB。
  • Conversation 内存最大 1 MiB。
  • Transcript 文件最多 1 MiB。
  • Child 交互 UI 请求自动 cancelled，防止永久等待。
  • Max-turn 超限先 steer wrap-up，再 abort。

持久化、恢复与有界输出

Run Store

  • .pi/mesh/runs/<runId>.json
  • 临时文件 + rename + file/directory fsync。
  • Run schema：pi-mesh.run/v2。
  • Attempt 终态证据：attempt-result.json。
  • 恢复优先读取 terminal evidence，避免重跑副作用。

Direct Registry

  • 按 sessionId SHA-256 前 16 位隔离。
  • 最多 1024 条记录。
  • Host restart 后 running/queued → stopped。
  • Persistent session 仅在显式 resume 时惰性重连。
  • 非 persistent 和 Worktree Agent 不可 resume。

输出边界

  • Direct/Mesh checkpoint preview：200 KiB。
  • 完整输出写 artifact。
  • Tool 文本默认 50 KiB / 2000 行。
  • 详情列表通常最多 256 项。
  • UI 标题最多 160 字符。
Registry 恢复时的路径/来源判定fail closed
  • record.cwd 必须等于 canonical project root。
  • Project Agent 必须位于项目 .pi/agents。
  • User Agent 必须位于 getAgentDir()/agents。
  • Bundled Agent 必须位于 package 的 BUNDLED_AGENTS_DIR。
  • transcriptPath 必须 canonical 位于 .pi/mesh/transcripts 且扩展名为 .jsonl。
  • sessionDir 仅允许 .pi/mesh/sessions 或 .pi/sessions。
  • symlink escape 被 canonical path 比较拒绝。

Mailbox、Growth 与 Host 审批

Child 身份判定

  • 必须提供 runId/nodeId/attempt/root 环境变量。
  • Run 必须 running。
  • Caller node 必须 running。
  • Caller attempt 必须与当前 attempt 相等。
  • 否则所有 mesh_control 操作拒绝。

Growth 三层防线

  1. Child 提案前检查 allowedSubagents。
  2. Host growth_decide 再检查 status、attempt、revision、allowlist。
  3. manager.grow() 再检查 requester active、allowlist、maxNodes、DAG cycle/depth。

Optimistic fence

// proposal
baseRevision = run.revision
requesterAttempt = currentAttempt

// approval
run.revision === baseRevision
requester.attempt === requesterAttempt
requester.status ∈ {running, paused}

Mailbox 限制

  • 默认单消息 32 KiB。
  • 默认单收件人未读总量 1 MiB。
  • 接收者必须是 Run 节点或 host。
  • 每收件人使用 lock file。
  • ACK 使用 claim file，60 秒后可回收 stale claim。
  • Durable spool 是 source of truth。

Git Worktree 判定与成果交接

启动前

  • 必须是 Git repository。
  • 主工作区必须 clean，dirty 时 fail closed。
  • 所有任务 CWD 必须属于同一 repo root。
  • setup hook 必须是文件，最大 120 秒。
  • 多 Writer 汇合需要显式 integration: true。

完成后

  • 有修改时自动 commit。
  • 生成 branch：pi-mesh/run/node-attempt。
  • 保存 binary patch 和 handoff.json。
  • 不自动 merge 主分支。
  • 无修改时删除临时 Worktree。
  • 清理失败保留 partial 状态和错误。

模型解析与 Cross-extension RPC

模型判定

  • Exact provider/id 优先。
  • 随后 normalize：小写、._ → -、去日期后缀。
  • 仅唯一 fuzzy match 可接受。
  • 不可用或歧义直接抛错，不 fallback。
  • 初始 Mesh 和 Growth tasks 都在 Host model registry 解析。

RPC v2

  • Protocol version 2。
  • active session 由 session_start 保存。
  • 无 active session 时 spawn fail closed。
  • 允许 keys：description/model/thinking/max_turns/isolation。
  • 额外 key 拒绝；max_turns 1–1000；isolation 仅 worktree。
  • Agent frontmatter 对 model/thinking/maxTurns 优先。

UI、通知与键盘判定

FleetView

  • 只在 ctx.mode === tui 绑定。
  • 刷新 200 ms；最多 5 行。
  • 完成任务 linger 5 秒。
  • Viewer 每 250 ms 刷新。
  • 宽度不足 60 时 overlay 不显示。

键盘冲突规避

  • 输入框非空时不接管。
  • key release 不接管。
  • 非 Editor focus 不接管。
  • Viewer 打开时主面板不接管。
  • stop/steer 前重新读取最新状态，拒绝 stale action。

通知 Join mode

  • async：立即 flush。
  • smart：默认 100 ms debounce。
  • group：250 ms debounce。
  • 按 Agent record id 去重。
  • 以 follow-up + triggerTurn 投递。

已接受的设计差异与剩余限制

以下不是当前 blocker，而是有意保留的产品/架构边界。

不是严格行为超集

  • Host 工具面覆盖并增加 mesh，但不逐项复刻 pi-subagents 全部细节。
  • Child 自主递归由 Host-approved growth 替代。
  • Operators 是 DAG topology presets。
  • 装饰性动画和精确 Claude Code 行样式未复刻。

测试与运行边界

  • 没有付费 provider live smoke test；真实 Pi loader、RPC 和 OS process 由确定性 mock 覆盖。
  • Async Mesh 的 usage 保存在 Run/Node 状态，不在原始异步 Tool result 聚合返回。
  • Project overrides 必须经过 Pi project trust。
  • ACP/text-frame、protocol repair、Reasonix、Bubble Tea 等明确不迁移。

当前控制姿态

默认拒绝、Host 最终控制、边界有界、终态单调、恢复基于证据。 Child 无权直接修改拓扑；资源、Agent 来源、模型、路径和恢复记录均在 Host 侧重新验证。需要关注的不是继续增加 Operator，而是未来若引入新的 Child 资源、跨 Session Fleet cap 或真实 provider 测试，应继续沿用同样的 fail-closed 和 bounded evidence 原则。
